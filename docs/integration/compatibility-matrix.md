# Compatibility and evidence boundaries

Discovery, packaging, invocation, delegation and runtime behavior are different claims. The ordinary Markdown skills are portable where a host supports that format. A successful copy/install or static manifest check does not establish native agent execution.

| Surface | Evidence/status |
| --- | --- |

| Remote archive installer | Executable local archive simulation through unchanged download/extract boundary; public remote publication is outside scope |
| npm package | Actual local npm pack, extraction, package CLI/API and selected installed consumer tested |
| Claude Code marketplace | Single Agentic manifest, strict validator; native adapted reviewer execution unverified |

| Third-party npx skills selected EGM directory copy | Self-contained installed-copy consumer reproduces the relevant package boundary; actual third-party CLI/network not exercised |

The Node API requires >=18, Git, origin URL and HEAD for handoff revision binding. The Bash installer remains usable without Node; handoff validation requires Node. Existing custom configs are preserved; no automatic plugin/global tool install or upstream update occurs. Unsupported fresh delegation blocks Goldfish, while direct Codinary requests retain their existing semantics and their independent-QA prerequisite.

Read-only was advisory, not host-enforced. This is one real adapted stage. A separate full five-stage adapted review-only fixture records its actual completion/results under runtime-probe/full-review/; consult its retained manifest rather than infer a pass here. Other native hosts remain unverified. Initial five-stage pinned-upstream proposal review and its capped readiness re-audit failed; neither is substituted for final implementation QA.
